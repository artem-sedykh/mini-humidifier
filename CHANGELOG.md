# Changelog

Every release of this card, newest first. Each heading links to the release it
came from, where the asset and the date are.

## [v3.3.0](https://github.com/artem-sedykh/mini-humidifier/releases/tag/v3.3.0)

The card stops redrawing itself twice a second, the `order` option on
indicators starts working, and the bundle is half the size it was.

### Fixed

- The card asked for a render every half second, for as long as it was on
  screen, whether or not anything it shows had changed. Its indicators compared
  an entity's `last_changed` against its `last_updated`, and those two differ on
  any entity that has been updated since it last changed state - so every state
  change anywhere in Home Assistant looked like news to them.
  [#162](https://github.com/artem-sedykh/mini-humidifier/issues/162)
- `order` on an indicator did nothing at all, though the reference has always
  documented it. The sort read a property that was not there, so it compared
  every pair as equal. Cards using a bundled model without their own `order:`
  are unaffected - each model already declares its indicators in the order it
  numbers them.
  [#171](https://github.com/artem-sedykh/mini-humidifier/issues/171)
- The `disabled` callback of `target_humidity` was handed `undefined` where its
  signature promises the current reading. No bundled model reads that argument;
  this matters if you write your own.
  [#163](https://github.com/artem-sedykh/mini-humidifier/issues/163)

### Changed

- The dropdowns are the card's own now. `@material/mwc-menu`,
  `@material/mwc-list` and `@material/mwc-ripple` are gone: they were last
  released in April 2024, required lit 2, and cost 95 KB of the bundle for a
  list of four modes. The replacement keeps the same look - Home Assistant's
  own surface, text and accent colours, the same 48px rows - and adds what the
  old one did not have: arrow keys, Home and End, Escape, and closing when the
  page scrolls under it.
  [#148](https://github.com/artem-sedykh/mini-humidifier/issues/148)
- **The bundle is 88 KB against 182 KB**, and lit is the only dependency left,
  down from four.
- The card registers its elements globally instead of through
  `@lit-labs/scoped-registry-mixin`. That mixin calls an API no browser
  implements - it belongs to a polyfill the card never shipped and the Home
  Assistant frontend happened to load. Where the polyfill was missing, the card
  rendered as an empty card and said nothing in the console. If you have ever
  seen that, this release is worth trying:
  [#72](https://github.com/artem-sedykh/mini-humidifier/issues/72) may be it.
  [#166](https://github.com/artem-sedykh/mini-humidifier/issues/166)
- The source is TypeScript, and the card is now tested in a real browser as
  well as in unit tests - 45 component tests that render it and drive it, on
  top of 172 unit tests and the assertions on the built bundle. Nothing about
  this is visible in a dashboard; it is what the three fixes above were found
  by.
  [#152](https://github.com/artem-sedykh/mini-humidifier/issues/152),
  [#156](https://github.com/artem-sedykh/mini-humidifier/issues/156)

Tested on Home Assistant 2026.8.3, in a browser and in the Android companion
app.

## [v3.2.1](https://github.com/artem-sedykh/mini-humidifier/releases/tag/v3.2.1)

No functional changes. The build toolchain was replaced, and the bundle this
release ships is 5.7% smaller over the wire as a result.

### Changed

- The minifier moved from `babel-preset-minify` to terser, and the bundler
  from rollup 2 to rollup 4. Both packages it replaced were last released in
  2020, carried unfixable advisories, and blocked every dependency update.
  Babel is gone from the build entirely: it targeted browsers far older than
  any that can run the Home Assistant frontend.

### Fixed

- The bundle contained two copies of `@lit/reactive-element`, one reached
  through `@lit-labs/scoped-registry-mixin` and one through `lit`. Nothing
  visibly misbehaved, but the duplicate was 11 KB of dead weight and left two
  competing update lifecycles in the same page.
- `lit/directives/style-map` and `lit/directives/class-map` were imported
  without the `.js` extension that lit's package exports declare. It happened
  to work; any change to module resolution would have turned those imports
  into unresolved externals.

## [v3.2.0](https://github.com/artem-sedykh/mini-humidifier/releases/tag/v3.2.0)

Adds a new device, and repairs the mode dropdowns of three models that had
been calling a service Home Assistant removed in 2023.7.

### Added

- Defaults for `xiaomi_miio_airpurifier:deerma.humidifier.jsq5`, contributed
  by @akovovh.

### Fixed

- The mode dropdown doing nothing on
  `xiaomi_miio_airpurifier:deerma.humidifier.mjjsq` and
  `xiaomi_miio:zhimi.airfresh.va2`. Home Assistant removed `fan.set_speed` in
  2023.7 and these two were missed when the other models were moved to
  `fan.set_preset_mode`. On `zhimi.airfresh.va2` the dropdown was empty as
  well, because it read its items from the `speed_list` attribute, which went
  away at the same time.
- Documentation links inside HACS. The reference moved into `docs/` in 3.1.6
  with relative links, and HACS renders the README through the Home Assistant
  frontend, where a relative link resolves against the wrong host and leads
  nowhere. All links are absolute now.

  HACS renders the README from the tag of the version you have installed, so
  this only takes effect once you are on 3.2.0.

## [v3.1.6](https://github.com/artem-sedykh/mini-humidifier/releases/tag/v3.1.6)

Home Assistant 2025.10 replaced the slider this card is built on, and the
target-humidity row collapsed onto the entity name. This release detects which
slider it is running against, so a single build covers every version from
2022.11 onwards. Nothing to change in your configuration.

### Fixed

- The target-humidity row collapsing onto the entity name on Home Assistant
  2025.10 and newer.
- The slider drifting away from the entity state after the first drag.
- Icon buttons rendering at the wrong size.
- `Cannot read properties of undefined` in the browser console whenever the
  entity went unavailable. The missing property is your language code; the card
  was reading translations through `hass.resources`, which the frontend no
  longer provides.

### Changed

- Documentation reorganised. The README is now a landing page, and the full
  option reference lives in
  [docs/](https://github.com/artem-sedykh/mini-humidifier/tree/master/docs).
  Install instructions, the list of supported models and troubleshooting were
  out of date and have been corrected.
- CI, the release workflow and the build toolchain brought up to date. The
  release job had been broken since GitHub retired the mechanism it used to
  build release notes.

### ADDED
- Added configuration for secondary_info, supported types `[last-changed, mode]`, default type `mode`
```yaml
- type: custom:mini-humidifier
  entity: fan.xiaomi_miio_device
  secondary_info: last-changed

- type: custom:mini-humidifier
  entity: fan.xiaomi_miio_device
  secondary_info: #default type mode, changing icon

```
- Added indicator `tap_action` configuration, #21
```yaml
- type: custom:mini-humidifier
  entity: fan.xiaomi_miio_device
  indicators:
    temperature:
      source:
        entity: sensor.temperature
      tap_action: more-info
    humidity:
      source:
        entity: sensor.humidity
      tap_action: more-info
```
- When you click on the button, it instantly changes its state, but if the actual state has not changed after `action_timeout`  
it returns to the previous state, default value `3500 milliseconds`
```yaml
- type: custom:mini-humidifier
  entity: fan.xiaomi_miio_device
  buttons:
    dry:
      action_timeout: 2000
    led:
      action_timeout: 2000
```

- The default configuration settings for buttons and indicators are placed in a separate file,  
now you can send a pull request or throw issue so that I would add your humidifier model an example for [zhimi.humidifier.cb1](https://github.com/artem-sedykh/mini-humidifier/blob/master/src/configurations/zhimi_humidifier_cb1.js)  
default model `zhimi.humidifier.cb1`
with this approach, the configuration in the yml file will be cleaner, and individual parameters can be redefined  

```yaml
- type: custom:mini-humidifier

  model: 'zhimi.humidifier.cb1'
```
